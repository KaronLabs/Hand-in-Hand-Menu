4. Codex에 `README.md`, `AGENTS.md`, 이 문서를 먼저 읽고 테스트·빌드 상태를 확인하도록 요청합니다.

## 기존 음식·칵테일 가격 수정

화면에 표시하는 데이터는 `data/menu.json`입니다. 해당 항목의 `id`와 이름을 확인하고, `price.single.amountKrw`에는 정수 원화 금액을, `raw`에는 같은 금액의 문자열을 넣습니다.

예를 들어 사장님이 23,000원으로 확인한 경우는 다음과 같습니다. 이것은 수정 방법 예시이며 현재 메뉴 가격을 변경한 것은 아닙니다.

```json
{
  "kind": "single",
  "single": {
    "amountKrw": 23000,
    "status": "verified",
    "raw": "23,000"
  }
}
```

과거 전사 파일은 원본 메뉴판을 옮긴 기록입니다. 새로 확인한 가격의 날짜·항목·근거는 `data/review-decisions.json`의 구조에 맞춰 기록하거나 별도 수정 기록에 남깁니다. 기존 원문과 동일한 가격을 가정하는 테스트가 있다면 확인된 새 가격과 근거에 맞게 갱신합니다.

## 위스키 가격과 메뉴 추가·삭제

현재 위스키 29개 행은 `whiskyUnitStatus: "unverified"`이며 화면에 `직원 문의`를 표시합니다. 잔·병의 가격 단위와 금액을 확인한 뒤 관련 데이터와 테스트를 함께 수정합니다. 한 항목만 확인됐다고 전체 단위를 확인 상태로 바꾸지 마세요. 부분 확인을 지원하려면 현재의 전역 단위 정책을 함께 수정해야 합니다.

현재 검증기는 최초 원본 메뉴판의 70개 행·출처·분류별 행 수를 고정해 검사합니다. 메뉴 추가·삭제·새 분류는 JSON만 편집하면 검증에 실패할 수 있습니다. Codex에 새 메뉴 구조에 맞춰 `src/core/menu.mjs`의 출처·행 수 규칙과 관련 테스트도 함께 갱신하도록 요청합니다.

## 배포하기

현재 운영 중인 원래 주소는 https://hand-in-hand-aperitivo-menu.hi-karonlabs.chatgpt.site/ 입니다. 현재 GitHub 저장소에는 자동 배포 연결이 없습니다.

- 원래 Sites 사이트를 계속 사용할 경우: 해당 사이트를 배포할 수 있는 계정·권한으로 게시합니다. GitHub의 포크 소유권만으로 이 권한이 생기지는 않습니다.
- 본인 계정에서 별도 Sites 사이트를 운영할 경우: Sites에서 새 사이트를 등록하고, 반환된 프로젝트 ID로 `.openai/hosting.json`을 연결해 게시합니다.
- 다른 정적 호스팅을 사용할 경우: 테스트·빌드 후 `dist/`를 배포합니다. 호스팅별 설정은 본인 계정에서 연결합니다.

소스 수정과 GitHub push를 마친 뒤 실제 공개 주소에도 변경 내용이 반영됐는지 확인해야 합니다. 배포 주소가 바뀌면 테이블 QR과 카드도 함께 교체합니다.

## QR 다시 만들기

공개 배포가 성공한 최종 주소를 사용합니다. 아래 명령의 URL은 기존 사이트를 계속 사용할 때의 값입니다. 새 사이트로 옮겼다면 실제 새 주소로 바꿉니다.

```bash
node scripts/create-qr.mjs https://hand-in-hand-aperitivo-menu.hi-karonlabs.chatgpt.site/ qr
```

이 명령은 `qr/hand-in-hand-table-qr.png`와 `qr/hand-in-hand-table-qr.svg`만 생성합니다. **카드 PDF는 자동으로 갱신되지 않습니다.** 새 QR로 카드 PDF를 다시 구성해야 하며, PDF 안의 QR도 최종 주소로 읽히는지 확인합니다.

현재 제공된 카드 PDF는 A6(105×148mm) 1페이지입니다. 인쇄 후 실제 손님 휴대폰으로 메뉴가 열리는지 확인한 뒤 테이블에 비치합니다.
